# Stock Report

面向上市公司财报研究的数据仓库。项目保存官方原始财报、结构化原始报表、标准化事实和可复核分析结果，首个研究对象是 `stock_analysis` 产出的 A 股 ROIC Top50。

## 当前角色

本仓库是公司研究的内部成果与追溯仓，不是读者入口。当前公司研究由`stock_analysis`统一Runner生成，已校验的`result.json`与`report.md`写入`data/analysis/stock_research/<code>/<period>/`；AH Note监听这些成果并形成唯一公开页面。

原始PDF、接口响应、历史资产结构复核和旧协议报告继续保留，不覆盖、不伪装为当前协议。当前协议为`stock-research-analysis-v2`，其公式、自审与估值口径由上游公司研究Bundle负责，本仓库只保存和追溯，不在发布层重新解释。

## 历史资产复核目标

默认对每家公司使用最近年报：

- 年末合并资产负债表：提供资产负债结构金额；
- 全年合并利润表和现金流量表：提供营业收入、毛利、归母净利润和核心现金流；
- 年报附注：判断定期存款、理财、战略投资、商誉、合同负债、存货构成等项目性质。

季度报告只在显式指定季度 period 时使用，用于年内跟踪或看最新变化。

核心勾稽关系：

```text
总资产 = 资金类资产 + 经营类资产 + 投资类资产 + 其他资产
总负债 = 融资负债 + 经营负债 + 投资性负债 + 其他负债
所有者权益合计 = 净资金 + 净经营资产 + 净投资资产 + 其他净资产
```

- 资金类资产：现金、现金等价物、可剥离存款和金融投资，不依赖主业继续经营即可变现。
- 经营类资产：应收、存货、合同资产、厂房设备、在建工程、使用权资产、无形资产等，与主业规模和盈利能力直接相关。
- 投资类资产：长期股权投资、战略股权、投资性房地产等，既非现金等价物，也不直接属于核心经营循环。
- 其他资产：商誉、递延所得税资产、待售资产和暂时无法可靠归类的项目。
- 融资负债：短期借款、长期借款、一年内到期非流动负债、应付债券、租赁负债等有息融资项目。
- 经营负债：应付票据、应付账款、合同负债、应付职工薪酬、应交税费和其他经营应付款。

核心净额：

```text
净资金 = 资金类资产 - 融资负债
净经营资产 = 经营类资产 - 经营负债
净投资资产 = 投资类资产 - 投资性负债
其他净资产 = 其他资产 - 其他负债
```

主勾稽使用合并报表所有者权益合计，同时单列归属于母公司所有者权益、少数股东权益和少数股东权益占比。最终报告首屏主表只展示资产端和负债端，不展示净额：

```text
资金：资金类资产 / 融资负债
经营：经营类资产 / 经营负债
投资：投资类资产 / 投资性负债
```

净额用于 JSON 勾稽和结论归纳，不放进首屏主表。资产端与负债端用于识别业务变化。`其他` 不作为常规主表行；其他净资产低于所有者权益合计 5%，且主要由递延所得税、应付股利、政府补助递延收益、普通受限保证金等常规项目构成时，可以不列示、不解释，但仍保留明细和公式勾稽。低于 5% 但包含非常规、不透明、一次性或可能改变判断的项目时，应在存疑或异常段单独说明。

每个类别还必须用简短文字解释主要构成，并写出金额。解释不能停留在“存货、应收款项融资、合同负债”等会计术语，而要尽量翻译成业务实物、权利或义务：例如存货应说明是原材料、在产品、自制半成品/基酒、成品酒、包装物或发出商品；应收款项融资和应收票据应说明是银行承兑汇票、商业承兑汇票还是其他票据；合同负债和预收款项应说明是否来自经销商或客户先款后货；固定资产和在建工程应说明是厂房、生产设备、包装、智能仓储、土地或软件等。

资产负债结构之后追加两张核心表：

- 利润核心：营业收入、毛利、归母净利润。
- 现金流核心：经营活动现金流净额、投资活动现金流净额、筹资活动现金流净额、现金及现金等价物净增加额。

Markdown 使用固定二级标题：`资产负债结构`、`利润核心`、`现金流核心`。每张表前写 `单位：亿元`。利润和现金流表只放核心数字；文字说明沿用资产负债表原则，只解释重要、异常、非常规、不透明或改变判断的业务动作。毛利必须用营业收入减营业成本计算，营业成本只进入 JSON 勾稽，不作为 Markdown 核心表字段。

报告标题下方必须展示当前股价，格式为 `当前股价：xx.xx 元/股（行情时间：...，来源：...）`。当前股价通过 `.agents/skills/a-share-price-fetch/` 的固定脚本获取，作为市场行情数据单独保存，不参与财报勾稽。

如果财报、业绩说明会、投资者关系活动记录、交易所互动问答或公告能够解释具体业务含义，应记录来源名称、日期、URL 或本地路径。对“监管商品”“监管商品款项”等不透明项目，不得硬解释；找不到可追溯证据时，必须明确写“财报仅列示科目，业务合同细节未披露”。

不确定项目不强行分类。金额重要时保留原始科目、分类依据、替代口径和复核状态。

## 数据目录

```text
data/
├── universe/                         # 研究股票池及来源
├── raw/
│   ├── filings/<code>/<period>/      # 官方 PDF 与元数据
│   └── statements/<code>/<period>/   # 数据接口原始 JSON
├── normalized/facts/                 # 标准化报表事实
├── analysis/asset_structure/         # 单家公司资产分类结果
└── outputs/                          # Top50 汇总表和报告
```

PDF 使用 Git LFS 管理；原始 JSON 和分析 JSON 直接进入 Git。生成型 SQLite、缓存和运行日志不提交。

## 分析原则

1. 原始披露与加工结果分开保存。
2. 每个加工值保留来源报告、原始字段和分类依据。
3. 父项、子项同时保存，并运行总资产勾稽。
4. 默认使用最近年报；显式季度模式下，若最新季报缺少附注，引用最近年报附注，但明确标记“沿用年报分类”。
5. 资金类资产和经营类资产是主表；投资类和其他类金额超过总资产 10% 时必须单独解释。

详细数据契约见 [docs/data-model.md](docs/data-model.md)。

## 运行

```bash
python -m venv .venv
.venv/bin/pip install -e .

stock-report import-universe /path/to/roic_top50.csv
stock-report import-annual /path/to/annual_reports
stock-report import-annual-reviews
stock-report run-latest --year 2026 --code 002315.SZ
stock-report run-latest --year 2026
PYTHONPATH=src python3 -m stock_report.asset_review_agent --code 002315.SZ
```

`run-latest` 会从巨潮资讯保存官方季度 PDF，从东方财富结构化接口保存未经改名的资产负债表响应，随后生成标准化事实、逐项目分类及汇总 CSV。`asset_review_agent` 默认使用 `2025-12-31` 年报口径；如需季度口径，显式传入 `--period 2026-03-31`。
